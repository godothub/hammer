# Hammer
使Godot像Hammer编辑器一样简单易用，让开发者专注于3D游戏内容开发。

## 项目架构

Hammer是以基于 `服务`、`数据`、`控制` 分离的思想开发的。在启动时，通过引擎的自动加载功能加载具有 `服务` 功能的脚本或场景，这些服务将通过项目设置和自定义脚本中的 `数据` 进行初始化，并在运行过程中由游戏脚本或用户界面进行 `控制`。


## 基础服务

> 注意：游戏主场景也归类为服务部分，因此在本框架的设计中，主场景中的节点应当专注于游戏互动或对服务进行简单的管理。

### 存档管理器(ArchiveManager)

存档管理器用于管理游戏中需要存储的数据。

### 游戏设置(GameSettings)

游戏设置是用于管理不随游戏变化的数据。

### 用户界面(UserInterface)

用户界面同时属于用户和控制和服务，是用户与服务交互的主要途径。


## 游戏功能

### 设施(Facility)

设施的激活状态取决于其依赖设施，每个设施都可以成为其他设施的依赖设施。当某个设施的依赖设施全部处于活跃(active)状态时，该设施就会处于启用(enable)状态。
